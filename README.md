# Astroolog

Персональный сайт нумеролога и коуча: Vue 3, TypeScript, Vite, Vuetify, Router, Pinia, Axios; Go, Gin, GORM; PostgreSQL 17. Для локализации добавлен vue-i18n; существующий стек и Docker Compose сохранены.

## Запуск

Из корня проекта:

```sh
docker compose up -d
```

В первом терминале:

```sh
cd backend
SEED_DEMO=true go run ./cmd/server
```

В другом терминале:

```sh
cd frontend
npm install
npm run dev -- --host 127.0.0.1
```

Сайт: http://127.0.0.1:5173. API: http://localhost:8080/api. PostgreSQL доступен с хоста на 5433. Backend использует существующий `backend/.env`.

`SEED_DEMO=true` добавляет четыре примера услуг и три явно обозначенных демонстрационных отзыва. Повторный запуск не дублирует записи и не перезаписывает изменения. При обычном запуске `go run ./cmd/server` демоданные не создаются. Отключение флага не удаляет уже созданные примеры: перед публикацией их нужно заменить или деактивировать в БД. Пользователь admin автоматически не создаётся.

## Реализовано

- Главная: hero, вопросы, описание подхода, направления, шаги, услуги, эксперт, отзывы и финальный CTA.
- `/about`, `/services`, `/services/:slug`, `/contacts`, `/privacy`, страница 404.
- Sticky header, полноэкранное мобильное меню с управлением фокусом через Vuetify, мобильная прокрутка отзывов, reduced-motion, клавиатурные focus states.
- Формы вопроса и записи: клиентская и серверная валидация, состояния загрузки, успеха и ошибки. Заявка сохраняется в БД; автоматическая отправка email/Telegram и админ-панель пока не реализованы.
- Страницы загружаются лениво. SEO title, description, OG-заготовки, alt, семантические заголовки. Это SPA: серверный рендеринг и prerender не подключены.
- Единый Axios-клиент, Pinia-каталог, TypeScript-модели. Цена предусмотрена как nullable integer в минимальных денежных единицах и временно не показывается.

## API

| Метод | URL | Результат |
|---|---|---|
| GET | `/api/health` | Существующая проверка API и БД |
| GET | `/api/services` | Активные услуги по sort_order |
| GET | `/api/services/:slug` | Услуга или 404 |
| GET | `/api/testimonials` | Активные отзывы из PostgreSQL |
| POST | `/api/bookings` | Создание заявки, 201 |
| POST | `/api/contact` | Создание обращения, 201 |

POST принимает JSON: `name`, `email`, необязательный `phone`, `message`, `consent: true`. Для записи обязательный `service_id`, необязательная `preferred_date` в формате YYYY-MM-DD (не в прошлом); сообщение необязательно. Для контакта сообщение обязательно. Поля ограничены по длине; размер тела запроса — 16 KB. Ошибки возвращаются как `{ "error": "…" }`, успех — `{ "message": "…" }`. Внутренние ошибки БД не раскрываются клиенту.

## База и архитектура

GORM AutoMigrate создаёт `users`, `services`, `testimonials`, `bookings`, `contact_requests`. Есть уникальные email и slug, внешний ключ booking → service, ограничения роли, рейтинга и статуса. Роли User: client/admin, хеш пароля исключён из JSON.

Backend разделён на models, repositories, services, handlers, middleware и routes. `main.go` сохраняет health check и подключает миграции/маршруты. Перед применением миграций к production следует использовать обычный процесс резервного копирования и проверки схемы.

## Перед публикацией

Нужны подтверждённые имя, биография, обучение и документы эксперта; настоящие фотографии; тексты услуг, цены и валюта; отзывы с разрешением на публикацию; email, Telegram/WhatsApp; сведения об операторе данных и согласованная политика конфиденциальности. Текущая политика — явно обозначенный черновик.

Контакты настраиваются через `frontend/.env.local` по примеру `.env.example`. Пока контакты не заполнены, посетитель видит форму вместо выдуманных адресов. При изменении VITE-переменных перезапустите Vite или пересоберите frontend.

Изображения: `frontend/public/images/`, происхождение и промпты — `ASSETS.md`. Заменяйте WebP по тем же путям либо измените ссылки во frontend и поле Service.image в БД. Портрет — вымышленный человек, созданный ИИ.

Для production: публикуйте `frontend/dist`, настройте SPA fallback на index.html и reverse proxy `/api` на Go:8080. Vite proxy используется только в dev. Укажите абсолютный публичный OG image URL/домен после их подтверждения. Хостинг в рамках этой задачи не изменялся.

## RU / LV / EN

Локализация интерфейса: `frontend/src/i18n/locales/ru.ts`, `lv.ts`, `en.ts`. Все языки проверяются по единой `MessageSchema`: пропущенный ключ вызывает ошибку TypeScript. Имена эксперта и клиентов, монограмма, бренд, email, телефон, URL и пользовательские сообщения не переводятся. У демоотзывов переводится только подпись «пример отзыва», сами имена остаются прежними.

`frontend/src/i18n/index.ts` подключает vue-i18n в Composition API mode. Первый язык и fallback — RU, язык браузера не учитывается. Переключатель `LanguageSwitcher.vue` меняет язык без перезагрузки. Настройка сохраняется в localStorage как `astroolog_locale`; неизвестное значение возвращает RU. При заблокированном localStorage сайт работает, но выбор не сохраняется после закрытия/перезагрузки.

Язык доступен в шапке на широких экранах и внутри мобильного меню на планшетах/телефонах. Переключение не сбрасывает введённые данные формы. Ошибки и успешные ответы сохраняются как состояние/ключи сообщений, поэтому также меняют язык. Встроенные сообщения Vuetify подключены к тому же vue-i18n через адаптер.

Маршруты остались прежними. Title, description, Open Graph и html lang обновляются при смене языка. Для деталей услуги SEO использует перевод из API. Слой локализации отделён от маршрутов, чтобы позже добавить языковые URL.

### Контент из PostgreSQL

Добавлены языковые поля (старые поля сохранены):

- Service: `title_ru/lv/en`, `short_description_ru/lv/en`, `description_ru/lv/en`, `duration_ru/lv/en`.
- Testimonial: `text_ru/lv/en`, `client_name_ru/lv/en` (для локализации подписи демоотзыва без перевода имени).

`backend/internal/database/translations.go` выполняет идемпотентное заполнение: пустое поле RU получает исходный текст; существующие значения не перезаписываются. `translations.json` содержит переводы только известных демоматериалов. LV/EN заполняются лишь при точном совпадении исходного русского текста, чтобы не подменить клиентский контент. Для новых или изменённых услуг редактору нужно заполнить соответствующие языковые поля.

API возвращает все языковые поля через прежние endpoints. `getLocalizedField(item, 'title')` в `frontend/src/i18n/localized.ts` централизованно выбирает текущий язык, затем RU, затем старое поле. Пустые строки, пробелы и null также дают fallback. Фотографии, цены, идентификаторы и ссылки не локализуются.

Ответы форм сохраняют прежние `error`/`message` и дополнены машинным `code`. Frontend локализует известные коды и использует локальное сообщение для неизвестной ошибки, а не выводит необработанный русский текст сервера.

### Проверка локализации

```sh
cd frontend
npm run test:i18n
npm run build
```

Тесты словарей и fallback используют встроенный Node test runner (Node 22.6+ с поддержкой strip-types; проект проверен на установленном Node 26). Для backend: `cd backend && go test ./...`. Браузерные проверки и скриншоты трёх языков сохраняются локально в `artifacts/`.
